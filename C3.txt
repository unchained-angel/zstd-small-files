# 10.1 Create a changed training set: `samples_v2`

We will simulate API evolution by taking your existing samples and adding a few new fields:

```text
schema_version
region

```

Run this block:

```bash
python - <<'PY'
import json
import pathlib
import random

random.seed(20260924)

src = pathlib.Path("samples")
dst = pathlib.Path("samples_v2")
dst.mkdir(exist_ok=True)

files = sorted(src.glob("*.json"))
if not files:
    files = sorted([p for p in src.iterdir() if p.is_file()])

count = 0
regions = ["eu-west-1", "us-east-1", "ap-south-1"]

for i, p in enumerate(files):
    try:
        obj = json.loads(p.read_text())
    except Exception:
        continue

    if isinstance(obj, dict):
        obj["schema_version"] = 2
        obj["region"] = regions[i % len(regions)]
        obj["priority"] = i % 5

        if isinstance(obj.get("tags"), list):
            obj["tags"] = obj["tags"] + ["v2"]
        else:
            obj["tags"] = ["v2"]
    else:
        obj = {
            "schema_version": 2,
            "payload": obj
        }

    out = dst / p.name
    out.write_text(json.dumps(obj, separators=(",", ":")) + "\n")
    count += 1

# If the original samples folder is too small, add synthetic v2 samples.
if count < 50:
    for i in range(100):
        obj = {
            "id": 10000 + i,
            "user": f"user{i:04d}",
            "email": f"user{i:04d}@example.com",
            "active": i % 2 == 0,
            "score": round(random.uniform(0, 100), 2),
            "schema_version": 2,
            "region": regions[i % len(regions)],
            "priority": i % 5,
            "tags": ["v2", "synthetic", f"batch{i % 7}"]
        }

        filename = dst / f"sample_v2_{i:03d}.json"
        filename.write_text(json.dumps(obj, separators=(",", ":")) + "\n")
        count += 1

print(f"Wrote {count} files to samples_v2")
```

# Step 11: Make the compression tool version-aware

Right now your original `compress.py` probably still expects:

```text
dictionary.bin
```

But we renamed it to:

```text
dictionary_v1.bin
```

and we also created:

```text
dictionary_v2.bin
```

So now we need a compression tool that can choose a dictionary version.

---

## Phase 1: The Gist

We will upgrade the compression tool so it can do this:

```bash
python compress.py example.json output.zst dictionary_v1.bin
```

or:

```bash
python compress.py example_v2.json output.zst dictionary_v2.bin
```

One-sentence version:

> The compressor must intentionally choose a dictionary version, while the decompressor later discovers the correct version from the Dictionary ID inside the compressed file.

---

## Phase 2: The Pitfalls

### Pitfall 1: Hardcoding one dictionary filename

Old beginner code often says:

```text
Always use dictionary.bin
```

But now we have:

```text
dictionary_v1.bin
dictionary_v2.bin
```

So the compressor needs to be explicit.

Minimal pair:

```text
Old compressor:
Assumes one fixed dictionary filename.

Version-aware compressor:
Accepts a dictionary file as an argument.
```

Self-correction script:

> Which dictionary version should this payload be compressed with?

---

### Pitfall 2: Confusing the compressor’s job with the decompressor’s job

The compressor chooses the dictionary.

The decompressor reads the Dictionary ID.

Minimal pair:

```text
Compressor:
Chooses dictionary_v1.bin or dictionary_v2.bin before compression.

Decompressor:
Reads the Dictionary ID from the compressed file and looks it up in registry.json.
```

Self-correction script:

> Am I compressing or decompressing? Compression chooses a dictionary. Decompression discovers the dictionary from the frame.

---

## Phase 3: The Hook

Think of the compressor as the **packing department**.

When the packing department prepares a package, it decides:

```text
Should we use phrasebook version 1?
Or phrasebook version 2?
```

It stamps the compressed file with a tiny luggage ticket:

```text
Dictionary ID
```

Later, the decompressor is the **luggage claim desk**.

It does not guess. It reads the ticket and asks:

```text
Which phrasebook matches this ticket?
```

Then it loads the correct dictionary.

Where the analogy breaks down:

> The compressed file does not carry the whole phrasebook. It only carries the ticket number. The receiver must already have access to the matching phrasebook.

---

## Phase 4: Why It Matters

This step is a prerequisite for real deployment.

In production, you may have:

```text
dictionary_v1.bin
dictionary_v2.bin
dictionary_v3.bin
```

The server needs to choose which one to use for new traffic.

Old compressed payloads still carry old Dictionary IDs.

New compressed payloads can carry new Dictionary IDs.

That is how you upgrade compression without breaking old data.

```bash
import pathlib
import sys
import zstandard as zstd


def main():
    # Usage:
    # python compress.py input.json output.zst
    # python compress.py input.json output.zst dictionary_v1.bin
    # python compress.py input.json output.zst dictionary_v2.bin

    if len(sys.argv) not in (3, 4):
        print("Usage: python compress.py input_file output_file [dictionary_file]")
        print("Example: python compress.py example.json example.zst dictionary_v1.bin")
        sys.exit(1)

    input_path = pathlib.Path(sys.argv[1])
    output_path = pathlib.Path(sys.argv[2])

    # If no dictionary is provided, default to version 1.
    if len(sys.argv) == 4:
        dictionary_path = pathlib.Path(sys.argv[3])
    else:
        dictionary_path = pathlib.Path("dictionary_v1.bin")

    if not input_path.exists():
        print(f"Error: input file not found: {input_path}")
        sys.exit(1)

    if not dictionary_path.exists():
        print(f"Error: dictionary file not found: {dictionary_path}")
        print("Make sure you are inside the project folder and the dictionary exists.")
        sys.exit(1)

    # Load the chosen dictionary
    dictionary_bytes = dictionary_path.read_bytes()
    dictionary = zstd.ZstdCompressionDict(dictionary_bytes)

    # Create compressor using that dictionary
    compressor = zstd.ZstdCompressor(level=3, dict_data=dictionary)

    # Read original data
    original_data = input_path.read_bytes()

    # Compress
    compressed_data = compressor.compress(original_data)

    # Save compressed output
    output_path.write_bytes(compressed_data)

    # Read back the frame header so we can show the Dictionary ID
    params = zstd.get_frame_parameters(compressed_data)

    print(f"Dictionary file: {dictionary_path}")
    print(f"Dictionary ID written into frame: {params.dict_id}")
    print(f"Input file: {input_path}")
    print(f"Output file: {output_path}")
    print(f"Original size: {len(original_data)} bytes")
```

# Step 12: Benchmark dictionary versions

Now we answer the practical question:

> Does `dictionary_v2.bin` actually help the new JSON shape?

And also:

> Does `dictionary_v2.bin` hurt or help old JSON shapes?

---

## Phase 1: The Gist

We will compare:

```text
vanilla zstd
dictionary_v1.bin
dictionary_v2.bin
```

against:

```text
old samples
new samples
single old example
single new example
```

The benchmark will measure compressed size, but it will also verify that every compressed file can be decompressed back to the exact original bytes.

One-sentence version:

> A benchmark is only meaningful if the compressed data can still be recovered correctly.

---

## Phase 2: The Pitfalls

### Pitfall 1: Benchmarking only one example

A single file can be misleading.

Minimal pair:

```text
One file:
May be lucky or unlucky.

Many files:
Gives a more reliable comparison.
```

Self-correction script:

> Am I comparing dictionaries on enough representative data?

---

### Pitfall 2: Comparing different payloads

You cannot fairly compare dictionary performance like this:

```text
dictionary_v1 on example.json
dictionary_v2 on example_v2.json
```

and conclude that v2 is better.

The payloads are different sizes and different shapes.

A fair benchmark compresses the **same input bytes** with each dictionary and compares the results.

Minimal pair:

```text
Unfair:
Different input files.

Fair:
Same input file, different dictionaries.
```

---

### Pitfall 3: Forgetting decompression correctness

The smallest compressed file is useless if it cannot be recovered.

Minimal pair:

```text
Compression-only benchmark:
Only measures size.

Round-trip benchmark:
Measures size and proves recovery.
```

Self-correction script:

> Did I verify that decompression returns the original bytes?

---

## Phase 3: The Hook

Think of this as an **A/B test between two phrasebooks**.

We ask:

```text
Does phrasebook v1 compress the old API language better?
Does phrasebook v2 compress the new API language better?
```

We do not just guess from the phrasebook’s cover. We test it on real luggage.

Where the analogy breaks down:

> In production, we do not always choose the “best” dictionary for every file. We choose the dictionary version that belongs to the payload generation, and the decompressor must match the Dictionary ID.

---

## Phase 4: Why It Matters

Before deploying a new dictionary, you want evidence.

You want to know:

```text
Does v2 improve new payloads?
Does v2 accidentally perform worse on old payloads?
How large is the difference?
```

This helps you decide whether the new dictionary is worth deploying.

---

# 12.1 Create the benchmark script

Run this whole block:

```bash
cat > benchmark_versions.py <<'PY'
import pathlib
import zstandard as zstd

LIMIT = 50


def load_dictionary(path):
    p = pathlib.Path(path)
    if not p.exists():
        raise SystemExit(f"Error: dictionary not found: {path}")
    return zstd.ZstdCompressionDict(p.read_bytes())


def make_compressor(dict_data=None):
    if dict_data is None:
        return zstd.ZstdCompressor(level=3)
    return zstd.ZstdCompressor(level=3, dict_data=dict_data)


def make_decompressor(dict_data=None):
    if dict_data is None:
        return zstd.ZstdDecompressor()
    return zstd.ZstdDecompressor(dict_data=dict_data)


def compress(data, dict_data=None):
    return make_compressor(dict_data).compress(data)


def decompress(comp, original_size, dict_data=None):
    # original_size helps if the frame does not store the content size.
    return make_decompressor(dict_data).decompress(
        comp,
        max_output_size=original_size + 1024
    )


def collect_files(directory, limit=LIMIT):
    p = pathlib.Path(directory)
    if not p.exists():
        return []

    files = []
    for f in sorted(p.iterdir()):
        if f.is_file():
            files.append(f)
            if len(files) == limit:
                break
    return files


def savings(original, compressed):
    if original == 0:
        return 0.0
    return (1 - compressed / original) * 100


def benchmark(name, files, dict_v1, dict_v2):
    print()
    print("=" * 60)
    print(name)
    print("=" * 60)

    totals = {
        "original": 0,
        "vanilla": 0,
        "v1": 0,
        "v2": 0,
    }

    for f in files:
        original = f.read_bytes()

        vanilla = compress(original, None)
        v1 = compress(original, dict_v1)
        v2 = compress(original, dict_v2)

        # Verify round-trip correctness
        assert decompress(vanilla, len(original), None) == original
        assert decompress(v1, len(original), dict_v1) == original
        assert decompress(v2, len(original), dict_v2) == original

        totals["original"] += len(original)
        totals["vanilla"] += len(vanilla)
        totals["v1"] += len(v1)
        totals["v2"] += len(v2)

    print(f"files: {len(files)}")
    print(f"original: {totals['original']} bytes")
    print(f"vanilla:  {totals['vanilla']} bytes "
          f"({savings(totals['original'], totals['vanilla']):.1f}% saved)")
    print(f"dict_v1:  {totals['v1']} bytes "
          f"({savings(totals['original'], totals['v1']):.1f}% saved)")
    print(f"dict_v2:  {totals['v2']} bytes "
          f"({savings(totals['original'], totals['v2']):.1f}% saved)")

    if totals["v1"] < totals["v2"]:
        print("Best dictionary for this dataset: dictionary_v1.bin")
    elif totals["v2"] < totals["v1"]:
        print("Best dictionary for this dataset: dictionary_v2.bin")
    else:
        print("dictionary_v1.bin and dictionary_v2.bin tied")


def main():
    dict_v1 = load_dictionary("dictionary_v1.bin")
    dict_v2 = load_dictionary("dictionary_v2.bin")

    old_files = collect_files("samples")
    new_files = collect_files("samples_v2")

    single_old = [pathlib.Path("example.json")]
    single_new = [pathlib.Path("example_v2.json")]

    benchmark("Old sample batch", old_files, dict_v1, dict_v2)
    benchmark("New sample batch", new_files, dict_v1, dict_v2)
    benchmark("Single old example", single_old, dict_v1, dict_v2)
    benchmark("Single new example", single_new, dict_v1, dict_v2)


if __name__ == "__main__":
    main()
PY
```

# Step 13: Automate the Training and Registration Pipeline

Right now, creating a new dictionary version requires running several separate Python snippets:
1. Generate/load samples.
2. Train the dictionary.
3. Compress a dummy file to extract the Dictionary ID.
4. Manually update `registry.json`.

In a production environment, you want a single, repeatable command to do all of this whenever your API schema changes. 

### Goal of Step 13
We will write a single script called `train_and_register.py`. When you run it, it will automatically train a new dictionary from a folder of samples, save it, extract its Dictionary ID, and update `registry.json` in one go.

---

## 13.1 Create the automation script

Run this block to create the script:

```bash
cat > train_and_register.py <<'PY'
import sys
import json
import pathlib
import zstandard as zstd

def main():
    if len(sys.argv) != 3:
        print("Usage: python train_and_register.py <samples_dir> <output_dict.bin>")
        print("Example: python train_and_register.py samples_v2 dictionary_v2.bin")
        sys.exit(1)

    samples_dir = pathlib.Path(sys.argv[1])
    out_dict_path = pathlib.Path(sys.argv[2])

    if not samples_dir.is_dir():
        print(f"Error: {samples_dir} is not a directory")
        sys.exit(1)

    # 1. Load samples
    print(f"Loading samples from {samples_dir}...")
    samples = [p.read_bytes() for p in sorted(samples_dir.iterdir()) if p.is_file()]
    
    if len(samples) < 10:
        print(f"Error: Need at least 10 samples, found {len(samples)}")
        sys.exit(1)

    # 2. Train the dictionary (10KB max size)
    print(f"Training dictionary on {len(samples)} samples...")
    dictionary = zstd.train_dictionary(10 * 1024, samples)
    out_dict_path.write_bytes(dictionary.as_bytes())
    print(f"Saved dictionary to {out_dict_path}")

    # 3. Extract the Dictionary ID by compressing a dummy payload
    cctx = zstd.ZstdCompressor(dict_data=dictionary)
    dummy_compressed = cctx.compress(b"dummy_payload_for_id_extraction")
    params = zstd.get_frame_parameters(dummy_compressed)
    dict_id = params.dict_id

    if dict_id == 0:
        print("Warning: Dictionary ID is 0. The dictionary might be too small or training failed.")

    # 4. Update registry.json
    reg_path = pathlib.Path("registry.json")
    registry = {}
    if reg_path.exists():
        registry = json.loads(reg_path.read_text())

    registry[str(dict_id)] = out_dict_path.name
    reg_path.write_text(json.dumps(registry, indent=2) + "\n")

    print(f"Successfully registered Dictionary ID {dict_id} -> {out_dict_path.name}")
    print("Updated registry.json:")
    print(json.dumps(registry, indent=2))

if __name__ == "__main__":
    main()
PY
```

# What is a CI/CD pipeline?

I think you meant:

```text
CI/CD pipeline
```

not:

```text
CI/ID pipeline
```

CI/CD stands for:

```text
Continuous Integration / Continuous Delivery or Continuous Deployment
```

A CI/CD pipeline is an automated assembly line for software changes.

---

## Phase 1: The Gist

A CI/CD pipeline automatically runs steps like:

```text
build
test
benchmark
package
deploy
monitor
```

whenever code, configuration, or data changes.

One-sentence version:

> A CI/CD pipeline is an automated process that safely moves changes from a developer’s machine into production.

---

## Phase 2: The Pitfalls

### Pitfall 1: Thinking CI/CD is only about code

CI/CD can also automate data-related changes.

In this project, the “change” might be:

```text
new JSON fields
new API schema
new payload patterns
new dictionary version
```

Minimal pair:

```text
Code CI/CD:
Automatically test and deploy application code.

Dictionary CI/CD:
Automatically train, register, test, and deploy dictionary versions.
```

Self-correction script:

> Is the thing changing only code, or is the data schema changing too?

---

### Pitfall 2: Thinking deployment means “push immediately”

A good pipeline can stop itself if something fails.

Example:

```text
Train dictionary_v3.bin
Run benchmark
If benchmark is worse than expected, stop.
If benchmark is good, deploy.
```

Minimal pair:

```text
Bad pipeline:
Automatically deploy everything.

Good pipeline:
Automatically test first, then deploy only if the tests pass.
```

---

## Phase 3: The Hook

Think of a CI/CD pipeline as a **factory assembly line**.

Instead of a human manually saying:

```text
Okay, train the dictionary.
Then remember to update the registry.
Then test decompression.
Then copy the dictionary to the server.
Then hope nothing was forgotten.
```

The pipeline says:

```text
When new samples arrive:
1. Train dictionary.
2. Register Dictionary ID.
3. Run compression tests.
4. Run decompression tests.
5. Run benchmark.
6. Deploy if all checks pass.
```

Where the analogy breaks down:

> A real factory produces physical objects. A CI/CD pipeline produces reproducible, tested software artifacts.

---

## Phase 4: Why It Matters

In production, you do not want to manually train and register dictionaries every time your API changes.

You want an automated process that can say:

```text
The API added new fields.
We collected new samples.
We trained dictionary_v3.bin.
We verified that it decompresses correctly.
We benchmarked it against v2.
It is safe to deploy.
```

For your zstd dictionary project, a CI/CD-style pipeline might trigger when:

```text
new JSON fields are added to API payloads
enough new sample data has been collected
compression ratio starts getting worse
a scheduled retraining job runs
a new API version is released
```

# Step 14: Harden `train_and_register.py`

There is one remaining production weakness.

Your current `train_and_register.py` can still silently overwrite things if used carelessly.

For example:

```text
It can overwrite registry.json mappings.
It can overwrite an existing dictionary file.
It can hide a Dictionary ID collision.
```

We saw exactly that when the fake `dictionary_v3.bin` replaced the `dictionary_v2.bin` registry entry.

So now we will add safety guards.

---

## Phase 1: The Gist

We will upgrade `train_and_register.py` so it refuses unsafe operations unless you explicitly use:

```bash
--force
```

One-sentence version:

> A production training script should fail loudly instead of silently overwriting dictionary versions or registry mappings.

---

## Phase 2: The Pitfalls

### Pitfall 1: Silent registry overwrite

Bad behavior:

```text
Dictionary ID already exists.
New dictionary is trained.
Registry is updated anyway.
Old mapping disappears.
```

Safe behavior:

```text
Dictionary ID already exists.
Script stops.
Registry is not changed.
User must explicitly force the change.
```

Minimal pair:

```text
Unsafe script:
“Same ID? I will replace the old mapping.”

Safe script:
“Same ID? Stop and ask a human.”
```

Self-correction script:

> Am I replacing a dictionary version, or accidentally destroying an old one?

---

### Pitfall 2: Overwriting an existing dictionary file

If this file already exists:

```text
dictionary_v3.bin
```

then this command:

```bash
python train_and_register.py samples_v3 dictionary_v3.bin
```

should not silently replace it.

Safe behavior:

```text
Error: dictionary_v3.bin already exists.
Use --force if you really mean it.
```

---

### Pitfall 3: Dictionary ID collision

A Dictionary ID is supposed to identify a specific dictionary.

If two different dictionary files claim the same Dictionary ID, decompression can become dangerous.

Minimal pair:

```text
Same ID, same dictionary:
Usually harmless duplicate.

Same ID, different dictionary:
Dangerous ambiguity.
```

Self-correction script:

> Does this Dictionary ID already belong to another dictionary version?

---

## Phase 3: The Hook

Think of `--force` as a safety cover.

Normal operation:

```text
Train new version.
If anything looks ambiguous, stop.
```

Forced operation:

```text
I understand this may replace something.
Do it anyway.
```

Where the analogy breaks down:

> In real production, even `--force` should usually be used only after backups, benchmarks, and review.

---

## Phase 4: Why It Matters

A registry is a source of truth.

If the registry loses the mapping for an old Dictionary ID, old compressed payloads may become unreadable.

For example, if this disappears:

```json
"903694296": "dictionary_v2.bin"
```

then files compressed with `dictionary_v2.bin` may fail or be decoded with the wrong dictionary.

That is why automation should be conservative.

Run this whole block:

```bash
cat > train_and_register.py <<'PY'
import sys
import json
import pathlib
import zstandard as zstd


def main():
    force = "--force" in sys.argv
    args = [arg for arg in sys.argv[1:] if arg != "--force"]

    if len(args) != 2:
        print("Usage: python train_and_register.py <samples_dir> <output_dict.bin> [--force]")
        print("Example: python train_and_register.py samples_v3 dictionary_v3.bin")
        sys.exit(1)

    samples_dir = pathlib.Path(args[0])
    out_dict_path = pathlib.Path(args[1])

    if not samples_dir.is_dir():
        print(f"Error: {samples_dir} is not a directory")
        sys.exit(1)

    if out_dict_path.exists() and not force:
        print(f"Error: output file {out_dict_path} already exists.")
        print("No changes were made. Use --force to overwrite an existing dictionary file.")
        sys.exit(1)

    print(f"Loading samples from {samples_dir}...")
    samples = [p.read_bytes() for p in sorted(samples_dir.iterdir()) if p.is_file()]

    if len(samples) < 10:
        print(f"Error: Need at least 10 samples, found {len(samples)}")
        sys.exit(1)

    print(f"Training dictionary on {len(samples)} samples...")
    dictionary = zstd.train_dictionary(10 * 1024, samples)
    new_dict_bytes = dictionary.as_bytes()

    # Extract Dictionary ID by compressing a dummy payload
    cctx = zstd.ZstdCompressor(dict_data=dictionary)
    dummy_compressed = cctx.compress(b"dummy_payload_for_id_extraction")
    params = zstd.get_frame_parameters(dummy_compressed)
    dict_id = params.dict_id

    if dict_id == 0:
        print("Warning: Dictionary ID is 0. Training may have failed or dictionary is too small.")

    reg_path = pathlib.Path("registry.json")
    registry = {}
    if reg_path.exists():
        registry = json.loads(reg_path.read_text())

    existing_file = registry.get(str(dict_id))
    if existing_file and not force:
        print("ERROR: Dictionary ID collision.")
        print(f"Dictionary ID {dict_id} is already registered to: {existing_file}")
        print("No changes were made.")
        print("If you really intend to replace it, rerun with --force.")
        sys.exit(1)

    out_dict_path.write_bytes(new_dict_bytes)
    registry[str(dict_id)] = out_dict_path.name
    reg_path.write_text(json.dumps(registry, indent=2) + "\n")

    print(f"Saved dictionary to {out_dict_path}")
    print(f"Successfully registered Dictionary ID {dict_id} -> {out_dict_path.name}")
    print("Updated registry.json:")
    print(json.dumps(registry, indent=2))


if __name__ == "__main__":
    main()
```
